# Task Brief

A brief supplies context and boundaries without adding unrequested planning work.

## State the task

- Outcome, why it is wanted, and who will use it.
- What to avoid: unwanted results, out-of-scope changes, unauthorized actions.
- Complete inputs, owned files or interfaces, and the shape of what to return.
- A check that can fail, chosen before work, and the evidence it must produce.

Leave the method open unless a particular method or interface is required.
A smaller model or one-turn worker needs complete inputs and an exact output
shape, not extra steps. Cut background, then examples; keep checks and output shape.

## Resolve uncertainty

Answer questions from available context first. Batch questions that change the
result; hold back only dependent work. Resolve optional wording choices with
stated assumptions. Do not invent missing material or assume a required reply.
Reuse existing authorization; obtain missing permission before destructive or
outward-facing actions. Finish reviewable preparation before asking for approval.

## Examples and checks

State your reading of a loose request briefly so errors show early.
For tone or format, give two or three differing examples and name traits to copy
and ignore; for code, name an existing file to follow. For independent takes,
use examples of format only; skip them when a fresh approach is wanted.
Prefer an executable test, deterministic comparison, observed behavior,
independent review against stated criteria, then human judgment. Assign who runs
each check. A worker without tools supplies evidence; its own "passed" is a claim.
Never relax checks. Use verification-before-completion if available.

## Delegate and hand off

Split independent work; keep coupled decisions with one owner and one integrator.
When delegating, request conclusions with paths or quoted evidence, not transcripts.
Before stopping, save verified progress, decisions and reasons, remaining steps,
checks and exact paths. Unattended work needs defined limits and a check; infer
them within the authorized task, never widen permission. Report exceptions first.
For competing subjective answers, keep the strongest distinct option and list
alternatives; combine complementary parts. Use the person's examples and rules.
Pause for a taste choice only if reserved for the person; essential questions still apply.
